# Segment prompt

Paste this into a new agent session. One segment per prompt; START_HERE.md runs the 8 segments of one bank, then stops for the user. Do not edit this prompt.

```text
Read SEGMENT_AGENT.md before you write any asm. It is the queue and the history. Take the first file in the ROM map that is not marked matched. That file is the only segment this session. Do not start the file after it.

NHLPA 93 SNES is a hybrid of NHL92 Genesis and NHLPA93 Genesis. NHLPA93 Genesis (https://github.com/abdulahmad/NHLPA93Genesis) is the source of truth for function, variable and label names. Use an NHL92 Genesis (https://github.com/abdulahmad/NHL92Genesis) name only where the SNES code follows 92G and 93G has no counterpart. Otherwise name by behavior. Read docs/discovery93snes.md for the known SNES-to-Genesis address matches.

The reference ROM is lst/nhlpa93snes.bin. The starting text is src/<file>.asm, generated by a quick pass: every instruction line has its address and bytes in the comment, and db lines are unresolved. Do not re-run tools/disasm65816.py over an edited file. Do not edit nhlpa93snes.asm except to add an include for a file you split out, in ROM order. Do not delete an asm file. Do not rewrite SEGMENT_AGENT.md as a whole file. Edit the current-segment line, the matched row, and the history in place.

Follow the rules already in SEGMENT_AGENT.md.

1. Run ./build.sh first. It must print MATCH before you change anything. If it does not, stop and report.
2. Trace the code in this bank: follow M/X (rep/sep/php/plp), D and DB. Turn unresolved db into instructions where code is reached (jump tables, pushed returns, jsl from other banks), and into labeled data, dw pointer tables, strings, or incbin assets where it is data.
3. Name everything in the segment, not just routines: every routine, local label, RAM variable, register/RAM parameter, constant and bit value, data table, and comment routines and non-obvious lines. Name them from the matching 93G routine (92G only when 93G lacks it), else by behavior; 92G names are kept as-is, inaccurate 93G names not from 92G are fixed. Comments follow the Comment rules in SEGMENT_AGENT.md (no other-game names, file/segment names, IDA references, ROM addresses or history in comments; history goes in docs/name_map.csv). Add RAM names to src/ram93snes.asm and hardware names from src/inc/snes_regs.asm.
4. Run ./build.sh after each batch of edits. It must print MATCH. Then add comments and run it again.
5. In SEGMENT_AGENT.md, mark that file matched with the byte count and range. Add a History line. Set Current segment to the next unmatched file. Do not mark the next file matched.

Stop after 5 failed builds in a row. Report the file, the first differing ROM offset, the built byte, the retail byte, and the line you wrote. Do not continue.
```
